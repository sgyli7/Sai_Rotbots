# Gorilla F 宏观共同设计探针

本快照保留 F0 的两种完整低腿承力原型、两种全机系统模块重排及液压保持功能的一手标定。它们是拒绝记录与下一设计输入；不是完整 F1 整机、外观改稿或稳定物理合同。原 AA3 / C15 111 件护甲没有修改。

## 实际结果与范围

- `architecture/report.md`：连续承力壳与成对封闭腹板都实际构建、计量和检查。仅覆盖一侧 knee 至脚托盘；仍有独立材料/原甲交，不能把 42–45 kg 的部分模块减去旧整机同名结构。旧 E2a 受限 LP 的眼部力只作截面敏感性，不是新方案不可避免的最小载荷。
- `packaging/report.md`：1585 件 E2a 全机库存内，123 件、10 个完整模块组作真实刚性移动，原甲、轴位及质量行保持。限定 moved-vs-rest 范围内的正体积交由 581 降到 517 / 548，两套仍拒绝；84 个相关路由未重建，不能继承旧流体位置、COM 或安装资格。
- `holding_reference/holding_sources.md`：从厂家完整阀块而非插芯质量标定局部保持功能；尺寸、接头、支架、动态应用和失压边界分别记录。LHK 22 G-21 的 0.85 kg 只属于裸完整阀块，不能当装好后的总模块，更不能用低振荡用途证明机器人闭环合格。LHDV 的完整调整端外形仍有未定尺寸。逐端口速度敏感点只校准流量需求，不证明同步动作或热能力。

两个几何分支与两套系统布局均已停止继续局部修补。下一步先在原外形内共同设计固定/输出关节堆栈与完整短腿段驱动，然后接回全机；当前没有证明 AA3 必须改形。

`rotary_reference/helac_rotary_route_screen.md` 保留另一条有界备选：型号专属运动力矩、保持力矩、安装方式、排量和压力边界分别核查。较大型号存在明显长度/法兰和自重取舍；旧 E2a 失败案例的力矩仅为敏感输入，不是新方案最低需求。这是目录窗口比较，没有实际原生装配或持续输出资格。官方原 PDF 正常下载返回 403，原文件哈希为空；本地事实与计算快照的哈希不冒充 PDF 身份。

## 来源与恢复

`snapshot_manifest.json` 记录每份原始路径、原始 SHA-256、存储 SHA-256 及字节数。大 JSON 用确定性 gzip 保存；脚本以 `.py.txt` 保存为可复现输入。厂家下载缓存不入库，研究文件保留官方 URL、可取得的哈希和缺口。

先按 [E2a 冻结说明](../internal_structure_e2/README.md) 恢复上游源，再运行本目录 `restore_snapshot.py.txt --root /absolute/checkout`，恢复到清单中的 `.scratch` 路径；现有不同字节的文件会被拒绝覆盖。各分支原有 manifest 与输入哈希保留原始含义，历史图不重绑定到后续版本。

研究 receipt 中的 OEM 缓存路径是来源记录；清洁环境不会自动得到这些下载字节。需要重新核查时从记录的官方 URL 取得并比对已有哈希；无法取得的原文件继续保留缺口。恢复与 hash 检查只覆盖本清单保存的字节，不声称恢复未随仓库分发的第三方原件。

所有物理、装配、安装、持续输出、热与审美门禁保持开放。当前完整候选仍为 E2a；本快照不新增能力评级。
