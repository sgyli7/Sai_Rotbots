# Gorilla 内部 D：分布模块与有限承力路径

D 是同一 C15 尺度下的真实装配诊断，**完整装配、外观和物理仍不放行**。它把 C 的杆线和旧 989 kg 混合预留替换为有限缸体、载体和全机模块，并回算新的质量、接触、输出和流量；不是已定型硬件，也没有证明 AA3 必须改形。

当前源是 [D 场景](../cad/source/internal_structure_d_scene.json)，SHA256 `2933318e60dfe786f5cae61d88682519589f1eb5f8a23c999e6f7c6566cdd280`。1482 个原生分件，391 行 C15 几何原样保留，其中 111 个护甲及六个接触候选面；其余 1091 个新件含有限承件、8 条腿部液压轴的实际材料、分段脚和 670 个全机模块。保留的旧上身显示机构不再加一次硬件质量，背屏原显示层对应新的完整硬件预留。原蓝白壳、原图比例、原配色没有改变，也没有成为新的审美基准。

[同源四视](../images/internal_structure_d_four_view.png)均为相同 3.04 m 正交尺度；TOP 是中立姿态，并非原稿 TOP 遮挡姿态复原。[拆壳斜视](../images/internal_structure_d_cutaway_threequarter.png)和[拆壳侧视](../images/internal_structure_d_cutaway_left.png)展示实际内部。拆壳隐藏项及理由写在 camera manifest；新实体和新模块没有因冲突而隐藏。原甲几何保持不变不等于外观已经合格：侧面露出的管路、上躯模块穿甲、臀部/踝脚装配仍影响整体审美。本轮不以新彩块或包壳遮挡这些问题。

## 接触、力与电热入口

四姿态 × 三个一致质量清单（全下界、中值、全上界）× 四载荷案例共 48 个条件案例：空载、100 kg 双手总候选载荷、该载荷重力 ×1.5 敏感性及独立 3 t 压力需求。3 t 不等于双手搬运能力；×1.5 不是实际动态轨迹。

48 例在法向地面、8 腿轴及4个等分脚撑锁假设内均有共同反力/容量 witness。最大假设利用率约 0.8664，在前伸姿态、全上界质量和 3 t 压力案例。法向平衡不等于摩擦/行走；未移重心的单左脚全部拒绝。压力假设是泵 21 MPa、缸供压 20.4 MPa、回油 0.3 MPa，并未验证阀损/保持、密封摩擦或持续容量。

每例记录 primal 方程、约束与非负边界残差，以及 HiGHS 数值 dual 乘子、下界和 gap。独立解析复核验证 +10/-20 N 的不对称容量及两轴共同分配；域外水平力、yaw 力偶和非平面接触拒绝。求解失败保留 unknown，不能直接当不可行证明。浮点 dual 不是严格区间证书。

[流量/功率报告](../evidence/internal_structure_d_power.json)把同版 dL/dq 与中立到姿态 2/4/8 s 恒速假设连接起来，108 个端点样本需求约 3.836–27.968 L/min。它们不是连续轨迹，未计加速度、扫掠、闭链支反力、旋转轴需求及独立变化的 COM。`Q=A·dL/dt`、`P=pQ` 与 `ΣF·dL/dt` 明示单位及方向。

两只 HAWE Z16 参照泵实际排量 **11 cc/rev**，3000 rpm 及自身容积效率敏感性 0.90–0.97 对应 59.4–64.02 L/min、21 MPa 下 20.79–22.407 kW；EMRAX188LC 的52 Nm/34 kW是原厂条件，不能把34 kW视为每个转速均可输出。[原厂参照及条件](../hardware/distributed_internal_component_references.md)保存来源。样本流量低于这一工作点不代表电力/热已过：泵多余流量必须变速/卸荷处理，负机构功须由阀控/蓄能/回馈吸收。当前样本固定压力输入流与有用功差额最大约16.013 kW，只是需解释的能量流，不是实测散热负荷；不能由此承诺续航。

散热/线束 299 个自有有限几何，约14.755/24.702/41.454 kg，有真实芯、风机、进/排风道及压力/回油/泄油/电线。14个冷却管段仍局限胸背，未接通23个关节冷却壳；冷却液占位还与容器底盖相交。完整液路、换热、风量、回流、关节和计算持续热红线继续开放。

## 同版拒绝和下一实际改量

四个姿态与原甲的正体积交数是595/599/603/596，包含精确自有条件材料和原厂/自有模块包络，不能将全部计作已知 OEM 内部钢碰撞，也不能当作美观评分；C 的旧计数覆盖不同对象，不直接比较。必须逐类型处理。

独立脚—踝接口核到每侧中立7对真实钢干涉，净交体积约75.741 cm³，四姿态持续存在；固定踝轴承壳碰足弓、固定撑和销。另有密封座/输出轴交；参考轴承包络单列。脚独立 neutral/fold 局部检查还看到托盘与固定足弓/撑的不同运动组实体相交。当前候选应被拒绝，不能切掉整条负载链或把两件归同body来隐藏冲突。

[红黄线](../evidence/internal_structure_d_gates.json)列出范围与关闭条件。下一周期优先**整条串联载荷路径共同设计**：髋 yaw/roll→pitch、膝/fold→踝/foot roll→独立前掌/跟；将主承壳、支承、驱动和脚弓统一做空间预留，再合回整机。肩腰厚臂的串联载体、真实动力分体及液路同步核定，不再独立补几根腿杆/更大锁销来代替完整装配。先寻找保持原壳的轴位/安装方向和共用承壳方案；若经明确约束仍需外壳包装改变，再委派包装 Agent 出同源四视，用户审美认可后才换基准。

## 复现和验证

使用现有 `.venv`，不执行依赖同步以免替换 CAD 依赖：

```bash
.venv/bin/python scripts/models/build_gorilla_distributed_foot.py
.venv/bin/python scripts/models/build_gorilla_distributed_layout.py
uv run --no-sync python scripts/evaluation/evaluate_gorilla_distributed_layout.py
uv run --no-sync python scripts/evaluation/screen_gorilla_distributed_power.py
.venv/bin/python scripts/models/render_gorilla_distributed_layout.py --views front,left,rear,top,cutaway_left,cutaway_threequarter --resolution 800 --samples 64
uv run --no-sync pytest -q
```

输入与builder哈希改变时，主装配器有意拒绝；需建立下一候选的spec重新绑定，不能覆盖本冻结候选或静默接受漂移。腿/系统源是自有native几何，外部 PDF/CAD 许可未知者不入Git；来源 URL、日期/参数及哈希保留。历史分支报告各自绑定原输入，尤其旧 leg root-foot 检查用的是临时旧脚，不移植为本版证据。

本版软件回归 **215 passed，86.27 s**；实际源/图/导出身份检查和各项独立只读复核另见[冻结清单](../../../experiments/gorilla_v0_1/internal_structure_d/snapshot_manifest.json)。实际资源审计：1482件源/GLB均闭合，1091新增严格匹配控制网格；391保留显示网格与冻结C15 GLB完全一致。严格raw-control判据仍有46个原有显示倒角差异，清单保留，未静默放宽判据。软件/资源检查只证明各自范围。MuJoCo/Bevy自由根、限力、自碰撞拒绝、真实双手/移动及长任务尚未进入本D候选；最终目标继续活动，不因这一阶段封存而完成。
